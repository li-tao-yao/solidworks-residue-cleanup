# 卸载与复查

**准备清单。** 记录产品版本、目标用户、自定义安装位置、用户创建的零件、模板和 Toolbox 库。Electrical 数据库可能含有多个用户的工程。移除实例或数据前，确认实例归属、数据用途和可恢复的备份。把安装介质、回滚用文件、历史记录与活动组件分开列出。

**产品与 SQL。** 优先通过该版本的 SOLIDWORKS 安装管理器移除产品。Electrical 失败或单独留下 SQL 实例时，使用匹配版本的 SQL Server Setup 选择那个实例。SQL Browser、Writer、驱动、共享管理对象及通用运行库可能服务于其他应用。仅有默认实例名或安装日期时还需要依赖证据。

**MSI 内部登记。** 在当前上下文查询产品代码，并与 Installer UserData 记录归属核对。5 表示已安装，1 表示已公告，2 表示为其他用户安装，−1 表示查询上下文未知此产品。普通卸载列表已空、实例也已移除，但专属产品仍为 5 时，取得本机产品代码并验证使用方，再通过 Windows Installer 正式卸载。保留 Installer 管理的缓存包。卸载后重新读取产品状态及对应登记。1603 时读详细日志，1618 时等其他安装结束，1605 时核对产品和上下文，3010 时记录待重启复查。[微软产品状态定义](https://learn.microsoft.com/en-us/windows/win32/msi/productstate)

**驱动与许可。** 对相应 RsFx 版本核对系统驱动枚举、服务注册键、服务控制管理器和驱动文件。即便驱动已停止，登记仍可能存在。仅在正式卸载已结束、文件和依赖均核实后，才考虑处理孤立的精确服务。保留其他软件运行中的许可证服务，读取许可配置时只取所需的存在性信息。

**文件与 COM。** 对每个候选目录解析绝对路径，检查子树、链接、访问错误和个人数据。自动诊断只检查路径是否存在，递归统计放在用户确认的具体目录内进行。手工检查 COM 时按 32/64 位和用户区分，沿 ProgID、CLSID、TypeLib 检查所有已注册的版本与实际服务器路径。某一版本已失效时仍应保护同一根下的其他有效版本。备份精确目标后再决定是否清理。

**分享诊断结果。** 默认摘要的 Rows 表示采集行数。报告中的 SharedComponent 表示该候选需要核实共享关系。服务名、路径和任务名可能带项目或用户名，原始安装日志及注册表备份宜只在本地查看。提供公开示例时使用合成数据。

**验收。** 在相同检查范围中复核目标 MSI、SQL 实例、32/64 位 SQL 分支、相关驱动、专属服务和文件，确认需要保留的应用可用。若其他账户的登记与当前 MSI 查询状态冲突，标明该账户尚待验证。重启和重装是否成功分别按实测记录。[SOLIDWORKS 卸载说明](https://help.solidworks.com/2024/english/Installation/install_guide/t_removing_installation.htm)
